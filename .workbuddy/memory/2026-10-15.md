## 紧急修复：首页一直 loading（bug）
- 现象：首页进入后一直显示加载（微信默认加载页转圈），页面内容不渲染。
- 根因：`utils/request.js` 写成 `module.exports = { request }`（对象导出），但首页 `index.js` 中是 `const request = require(...)` 后直接 `request(...)` 当函数调用 → `request is not a function`，`onLoad` 抛错，页面渲染失败。
- 修复：将 `request.js` 改为 `module.exports = request;`（直接导出函数本体）。index.js 调用方式不变。
- 验证：用 Node 模拟小程序环境跑 onLoad，修复后 `loading=false`、`showShops=5`，正常。其余 util/mock/storage 均为「对象导出+对象方法调用」，无同类隐患。

## Bug 修复：点单页数量变 11/111/1111（本次）
- 现象：进店点单，1 份拍黄瓜按加号变 11，再变 111。
- 根因1（直接原因）：WXML data-* 取出的 dataset 值均为字符串。规格弹窗底部步进器 `specCount` 直接 `count + dataset.delta`（1+"1"）→ "11"，连环拼接。连带症状：confirmSpec 的 `for (i < m.count)` 遇到 "11" 会真实加购 11 次。
- 根因2（显示层）：shop.js `refreshCart` 映射 cartItems 时漏了 `goodsId` 字段，导致聚合 `counts[it.goodsId]` 全部落到 "undefined" 键，商品列表角标永远显示 0（加购成功也不显示）。
- 修复：shop.js `specCount` 改 `parseInt(dataset.delta,10)||0`；refreshCart map 补 `goodsId: it.goodsId`；防御性规范：`pickSpec` 的 gi/oi、review.js `setStars` 的 n 均 parseInt。
- 验证：Node 复现旧逻辑=1111(string)、新逻辑=4(number)、聚合键 {"201":2,"202":1}；两文件 --check 通过；data-delta 仅 shop.wxml 规格弹窗使用，已全覆盖。
- 教训：小程序 dataset 值一律是字符串，参与运算/下标前必须显式转型（本类隐患已全项目排查：splice("0") 安全、WXML 比较会强转，仅上述两处有实害）。
